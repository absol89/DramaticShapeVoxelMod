**Review cleanup (uncommitted):** `68aec4e`'s nonfunctional

`StadiumModels` bridge and tests from `Stadium2ImportBattleArtVoxelFork`.
The Interface Sprites launch crash is fixed. The temporary Rival-3 logger was

cards remain active until that public API is supplied. The cache round-trip
probe is now forward-declared before `bindStorage()` uses it, and cache purge
also invalidates the active storage-byte facade rather than only filesystem

**Title/summary follow-up:** the original interface hook returned a Gen 2-5
atlas path to screens that only load one static image. That drew every frame as
one huge, miscentered sprite and let the title SGB palette recolor it. Review
cleanup now adapts `TitleState.currentSprite/update` and Gen 1
`SummaryMenu.new/update/draw` to prepared true-color frames with metadata
timing. Path-only callers retain ROM art for atlas generations. The title's
stock true-color replay excluded Red's complete rectangular bounds, which cut
a sharp box through a Pokémon effect even where the trainer image was
transparent. Review cleanup now emits alpha-aware one-row replay runs: an
opaque trainer pixel stays above the Pokémon, while transparent trainer space
restores the full-color front. The decoder/title adapter is explicitly covered
for Gen 1 static and Gen 2, 3, 4 and 5 animated fronts. A legacy 0.1.83 retest
then exposed two engine-version differences: that TitleState moves the mon via
pixel-valued `monOffset` rather than modern `slideIn`, and reconstructs Red from
three atlas quads while moving the ball quad separately. The replay now follows
the exact legacy offset and masks the composed trainer pixels, so Pokémon colors
remain identical on both sides of Red's boundary. A second device retest showed
that 0.1.83 cannot read pixels back from a LOVE Image at all, so the alpha path
was still falling back to Red's complete rectangle. `BattleArt.prepareData`
now retains its prepared ImageData weakly, and the legacy trainer mask reads
the resolved source PNG through `Assets.imageData`. The original overlapping
title placement and swoop are retained, with alpha-correct color while the mon
crosses behind Red. `DexEntryMenu` is now
an Image-frame adapter too: Gen 1 static and Gen 2–5 animated selected fronts
replace its ROM image and advance with the authored atlas timing. TitleState
bottom-aligns the complete frame canvas, which made species with transparent
rows beneath their feet float above Red's baseline. The adapter now finds the
minimum bottom padding shared by every frame and uses a title-only prepared
copy with exactly that transparent strip removed. The opaque foot row therefore
lands at y=135 for grounded frames, while using one constant crop across the
whole sequence preserves authored jumps/bobs and cannot clip an opaque pixel.

**Overworld follow-up:** the first 32x32 canopy hull in Viridian Forest was one
large unsliced operation inside an otherwise cooperative mesh job. The round
template now checks `BuildBudget` throughout its classification, flood, chord,
and face loops, so cache generation cannot freeze camera/input. A cold warp now
queues BODY before FULL, and `VoxelScene` only reuses its completed-frame canvas
for the same map ID; Viridian Forest can no longer display the adjacent area's
exit frame while its own mesh builds. Building rear walls also no longer copy
facade door tiles: `building_back_tiles.OVERWORLD`
maps the two upper door halves to wall tile 10 and the lower halves to base tile
26 (preferring the nearest matching 10/75 wall course), while the south/front
face keeps its original art. `CACHE_REVISION` is
bumped from 2 to 3 so an existing revision-2 house mesh cannot mask the fix.
`building_back_templates.OVERWORLD` limits this to exterior homes, commercial
houses, Centers, Marts, Oak's Lab and Day Care; interior tilesets are untouched.

**Precache diagnostics follow-up:** the completion screen's `AUX: 0` was a
reporting error, not 222 missing auxiliary records: Windows-safe storage names
that product `/deco`, while `stats()` still counted only the reserved `/aux`
name. The observed 480 files are exactly 222 FULL + 36 BODY + 222 DECO. The
counter now accepts `/deco` (and legacy `/aux`), and each genuinely failed job
is written to `mod-derived/BATTLE_ART_VOXEL_FORK/precache-failures.tsv` with
map, FULL/BODY slot, stage, logical key, physical `.bavc` path and error. The
mesher now hands a settled coroutine exception to that journal instead of
discarding it after a console-only warning. The first captured journal narrows
the five failures to `SAFARI_ZONE_CENTER`, `SAFARI_ZONE_EAST`,
`SAFARI_ZONE_NORTH`, `SAFARI_ZONE_WEST`, and `VIRIDIAN_FOREST`: both products
are absent for every FULL job and no encoder/storage call failed, placing the
fault in their shared Forest/Safari geometry build. A rerun with the enhanced
journal captured `Structures.lua:958: attempt to compare number with boolean`.
The 32×32 canopy call omitted the `taperVox` placeholder, passing its intended
`pinBase=true` into that numeric parameter. Adding the missing `nil` repairs all
five maps. The canopy regression now resumes past its first budget yield and
through completion; this is important because the bad parameter was not read
until after that yield, which is why the earlier scheduling-only check passed.
The
Pokémon Center/other facade-back treatment remains a separate later geometry
project; this pass does not touch interior models or broaden entrance rules.

## 1. Interface Sprites (a/b) — committed `e93e7c3`

**Goal:** show BATTLE ART's selected-generation FRONT in the non-battle interfaces (title, Pokédex, status/party, hall of fame, trainer card), **independently toggleable** of `DUPLICATE FIX: MODDED` (which owns only battle pictures). The status-screen HP bar remains owned by the engine's canonical tile renderer.

**Files:**
- `lib/InterfaceSprites.lua` (NEW) — owns the feature:
  - `pokemon.sprite` seam: only a **BACK** slot keeps the engine back (fixes the flipped-sprite bug where our front landed on the summary's left/back card). Front, nil-side, and the **title screen's cycling mon** (which passes a non-`"front"` side) all get our front. The title was previously wrongly excluded by an over-strict `side ~= "front"` guard.
  - `installSummary()` wraps `SummaryMenu.new/update/draw` to install one prepared atlas frame and advance it using the generated timing metadata. It does **not** redraw HP: `SummaryMenu` already calls `HudTiles.drawHPBar(data, 11, 3, mon, 1)`, whose fill starts at `(104,24)` and uses six shaped segment tiles plus the type-1 cap.
  - The sprite hook records a title/summary provider path before declining to return an undecoded atlas. This lets the Image adapters slice a compatible atlas supplied by another mod when the clean redistributable build lacks private PNGs. Metadata bounds checks reject an ordinary ROM image as an atlas.
  - `ourFront(ctx)`: regular form only (no shiny/DV); STATIC → `front-static/<slug>.png`; ANIMATED title/summary → prepared timed Image frames; other path-only animated interfaces retain ROM rather than drawing a complete atlas.
- `main.lua` — requires `InterfaceSprites`; adds the `InterfaceSprites.setting` (`ModSetting` `off`/`battle_art`/`modded`) to `SETTINGS`; calls `InterfaceSprites.install()`; **moved DROP MESH CACHE out of OPTIONS into the pause-menu CACHE → DROP action**.
- `lib/Structures.lua` — `roundTemplate` `pinBase` param drops cylinders/trees to y=0 so they sit ON terrain (floating-geometry fix, verified grounded on-device). Applied at the cylinder (N=32) and tree call sites; planter left unlifted.
- `lib/VoxelMeshDisk.lua` — `Disk.purge()` (delete on-disk mesh cache). NOTE: dev's `storageRoundTrips` cache-stall probe is preserved; live had lost it.
- `lib/ChunkMesher.lua` — `ChunkMesher.purgeCache()` (drop live GPU/RAM + on-disk cache).

**Engine basis (verified):** other mods wrap `pokemon.sprite` and `SummaryMenu.draw`; the title's cycling mon resolves through `pokemon.sprite` with `kind == "title"`. The 160×144 virtual canvas is resolution/aspect-independent.

**Front-only (owner decision):** status/party shows our front, never a back. Back sprites on the stats screen keep the engine's back.

## 2. Rival / Kanto Ascendant compatibility

**Finding (verified in code, not guessed):** Kanto Ascendant uses `OPP_RIVAL1/2/3` for its character/rival story. Battle Art **does not** redefine those trainer records or their pics — it only sets the runtime `battle.trainerPic` field via `replaceTrainerField` when *we* supply a trainer image for that key.

- `data/gen6_battle_backgrounds.lua`: `CERULEAN_CITY = { OPP_RIVAL1 = "bridges" }` — the Cerulean bridge background is keyed to **map + class**, so only the `{CERULEAN_CITY, OPP_RIVAL1}` fight gets `bridges`; `OPP_RIVAL2/3` and the Champion class keep their plates. Comment at line ~198 states this explicitly.
- `lib/BattleArt.lua` `applyTrainers`: `enemy = battle.showEnemyTrainer and trainerKey(battle) or nil`; `replaceTrainerField(battle, "trainerPic", BattleArt.trainerImage(enemy) or nil)`. For a rival key we don't handle, `trainerImage` returns nil → `replaceTrainerField` restores/leaves the rival's own pic. The bridge background and the rival sprite are independent; applying one does not replace the other.

**Compatibility target:** Battle Art 1.9.6. No code change was needed for Kanto Ascendant's rival system to work — Battle Art already preserves the rival identity/sprite while drawing the bridge background.

## Conventions / guardrails for the reviewer
- Each fix is its own incremental, **unpushed** commit (owner cherry-picks good fixes).
- **Never** commit ROM-derived or battle/asset art to git (`.gitignore` blanket-ignores `assets/battle/**`).

- Mod API 2; `V.require` loads sibling modules; `ModSetting` has no change-event (read/write/`sync` only).
- **Live↔dev divergence warning:** live is an older base + session edits and had **lost** dev's `b1a457a` cache-stall probe. When syncing live→dev, apply only isolated additions; do NOT overwrite dev's `VoxelMeshDisk.lua` wholesale or the probe is deleted.
